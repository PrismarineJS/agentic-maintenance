# Default-branch policy rollout

Date: 2026-10-06T05:49:24.054633+00:00. Source: live GitHub API readback, CI logs, and authorized Astra-agent maintenance changes.

Of **94** public, unarchived repositories, **94 require PRs** under the new review rule and **35 have the full policy active**. **59 still need CI prerequisites**. Administrators retain the PR-only approval exception; the CI/history ruleset has no bypass wherever active. GitHub billing and organization plan were not changed.

Created 50 repository-specific CI prerequisite PRs: 40 merged and 10 still open. Also merged [the pilot policy/CI PR](https://github.com/PrismarineJS/agentic-maintenance/pull/3) and [the monotree updater migration](https://github.com/PrismarineJS/prismarine-monotree/pull/5). Replaced 16 exact-default-branch classic rules only after their replacement rulesets were active. Other branches, three archived repositories, and one private repository were excluded.

## What was applied

- `pjs-pr-and-review`: one approval for ordinary mergers, repository-admin (role 5) bypass only through a PR. No `always` bypass or automation exception.
- `pjs-ci-and-history`: require GitHub Actions `ci` (integration 15368), require an up-to-date branch, block force pushes and deletion, no bypass. This ruleset remains **disabled** on the explicitly deferred repositories.
- Existing suites and OS/Minecraft matrices are preserved. The final gate runs with `always()` and rejects failed, cancelled, skipped, missing, or empty-matrix prerequisites. Version preparation validates the authoritative version list. Deployment/report-only jobs are excluded explicitly.
- Minecraft-data combines schema/data validation with its existing Bedrock consumer tests through a reusable workflow. The open packet-dumper prerequisite proposes consolidating its PR jobs, but activation is deferred until its output and error handling are asserted.
- The monotree manual updater now opens/updates `automation/update-trees` instead of pushing to the default branch. Existing scripts/history are preserved. Its installation CI passed; the actual updater was not dispatched. Shared release tooling already uses PRs. The archiver pushes to external GitLab/Codeberg repositories, outside these GitHub default-branch rules.

## Validation and limits

- Sixteen offline tests pass, including policy bypass boundaries, error/redaction handling, active-vs-disabled ruleset coverage, and CI gate negative cases.
- Pilot PR #3 merged with passing CI and no approval under the new rules. [Temporary PR #4](https://github.com/PrismarineJS/agentic-maintenance/pull/4) demonstrated that both a failed mandatory job and a skipped mandatory job fail `ci` and produce a blocked merge state. It was closed without merging.
- A final source-level coverage check found three empty/log-only suites, an import-only Forge test, a score-only challenge harness, and a render/unmount-only UI test after their green CI prerequisites had already merged. The six newly enabled CI rules were disabled again; their PR rules remain active. The affected web-client and website classic protections were restored first. Packet-dumper was deferred before activation because its empty unit test and error-tolerant extraction runs do not establish reliable assertions. These corrections are recorded explicitly in the JSON; passing test counts alone were insufficient evidence.
- Each final full-policy activation uses the exact inspected PR head, a passing real suite, an unchanged base, and fresh CI checks. Repository rule payloads and effective default-branch rules are read back.
- Automatic approval review rejected a proposed direct-ref update against the live pilot default branch. It was not executed or retried. Direct/force-push denial and ordinary-user permissions were checked through configuration; they were **not** tested with live writes or a separate non-admin account. No attempt was made to merge a failing PR.
- A settings match certifies configuration, not comprehensive test coverage or immunity to intermittent failures. Deferred repositories are not represented as fully protected. No skipped suite, empty test, lint-only command, or install-only job was substituted to obtain a passing gate.
- The settings audit is read-only. New repositories still need explicit provisioning on GitHub Free. No scheduled automation was added.

## Completing deferred repositories

For an open CI PR, fix its real suite or environment while retaining its tests and matrix, update the PR against the current default branch, and rerun. Once the complete gate succeeds, activate the saved CI ruleset and reconcile the exact classic rule. Do not force-merge a failing gate or grant an admin CI bypass. Repositories without meaningful validation need a small repository-specific test/validation design first.

## Evidence and rollback

The [rollout JSON](default_branch_policy_rollout.json) records CI links, tested heads, merges, rule IDs and replaced classic settings. The [post-rollout audit](default_branch_policy_after.json) provides replayable GET-only settings evidence, and [its Markdown diff](default_branch_policy_after.md) shows remaining drift. [The original snapshot](default_branch_policy.json) preserves the pre-rollout settings.

To reverse a full activation without creating an unprotected interval, restore its saved exact classic rule first, then disable the new rulesets. CI workflow changes can be reverted through PRs. If no previous classic rule existed, disabling the review ruleset reopens direct pushes, so that rollback needs an explicit decision. Do not delete unrelated or wildcard rules.
