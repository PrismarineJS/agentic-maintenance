## How the skills contributed

The protocol/data skill directed checks through actual compiled codecs and allowed dependency releases, both revealing a legacy-sneak compatibility regression and removing two unsupported objections. The behavior/test skill prompted distinguishing geometry and lifecycle inputs: a real slab shape, an unsupported texture entry, a final permitted bridge step, and idle flight in fluids. Architecture checks followed ownership of effective attributes, registered render groups and dependency state. Code-quality checks found missing declarations for the new protocol client API and viewer host extension contract.

These are recorded contributions during an unblinded review, not proof that skills alone caused the findings. The historical comparison and its limitations remain in [evaluation.md](evaluation.md). The evaluated skill files were kept frozen during this pass.

Checks range from static caller/type inspection to real codecs, NMP client/server tests, production physics with controlled worlds, and actual Three.js geometry with controlled loaders. Each record states its dependency versions and limits. A local protocol server is not a vanilla-server run, controlled rendering is not a WebGL screenshot, and related passing checks do not establish a complete end-to-end integration.

New reviews were independently checked through GitHub for COMMENTED state, exact commit, attribution, skill names and inline paths/lines; [publication audit](u9g_publication_audit.json). Corrective replies were checked against their original thread IDs and bodies; [correction records](u9g_corrections.json). [Independent code cross-checks](u9g_independent_checks.json) retain their conclusions and limits.
