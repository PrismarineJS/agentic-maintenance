# PrismarineJS code quality review

Assess the current patch and its callers. A useful finding identifies a concrete confusing contract, repeated source of drift, unhandled completion path, or measurable maintenance cost. Separate a necessary repair from optional cleanup. Historical comments below are attributed account evidence with undisclosed manual authorship, not an infallible rulebook; keep replies and retractions in view.

## Review the changed responsibility

**Abstractions must earn their cost.** For a new helper, getter, setter, or option, identify the actual consumer and the semantic work it supplies. Check whether it enforces an invariant or merely hides an obvious property update. Prefer an understandable local operation when the new public method adds no useful contract, as in [item109](https://github.com/PrismarineJS/prismarine-item/pull/109#issuecomment-1660487214). This does not prohibit classes or meaningful accessors. Do not demand extraction simply because code repeats: name the repeated invariant and show why future edits could diverge.

**Property access should have understandable mutation and cost.** If a getter decodes data or returns a computed object, trace whether a caller's edit affects stored state. Identify discarded mutations or repeated expensive work before suggesting construction-time normalization; account for later updates and invalidation. [Item110](https://github.com/PrismarineJS/prismarine-item/pull/110#issuecomment-1660498932) exposes the confusing copy/edit/set pattern; [item126](https://github.com/PrismarineJS/prismarine-item/pull/126#issuecomment-2683151129) questions substantial repeated decoding. These scoped criticisms do not authorize rewriting every existing getter.

**Names and branches should reveal the domain.** Ask for a precise name when an ambiguous field hides which session, lifecycle, or representation it describes. Simplify duplicated branch setup when it obscures the real variation, while preserving meaningful version differences. Keep comments that explain surprising protocol semantics. Treat readability cleanup proportionately: [protocol1277](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1277#pullrequestreview-1799704432) criticizes duplication and `_session` yet approves the small fix.

For a validator or audit, follow each exemption and early return that can turn a detected failure into success. Check the intended boundary with a distinguishing input; finding one faulty exemption does not cover its siblings. Preserve deliberate supported exceptions rather than demanding every bypass be removed.

**Public API changes include their usable contract.** Follow changed arguments, return values, events, and defaults into declarations and documentation. Public methods need accurate types/docs; internal underscore helpers should not accidentally acquire stable-API promises. [Mineflayer2929](https://github.com/PrismarineJS/mineflayer/pull/2929#discussion_r1108936010) explicitly distinguishes these choices. For declaration fixes, verify the real consumer compile path and existing runtime export shape: [world115](https://github.com/PrismarineJS/prismarine-world/pull/115#issuecomment-1384653927) directs a type export into declarations rather than changing CommonJS runtime exports.

## Check mechanics before prescribing cleanup

**Trace completion and error ownership.** When callbacks, promises, listeners, or timers change, locate who observes failure and completes cleanup. An async callback is valid JavaScript; the question is whether its returned promise/rejection is consumed, not whether `async` and callbacks are categorically incompatible. [Protocol1409](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1409#discussion_r2329203808) motivates this check, with its literal language claim deliberately narrowed. Likewise, distinguish essential parsing from optional diagnostic interpretation: [protocol1303](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1303#discussion_r1623673367) accepts ignoring a failed interpretation of otherwise valid chat text. Distinguish the returned operation promise from an unobserved cleanup chain before alleging swallowed errors; [mineflayer2833](https://github.com/PrismarineJS/mineflayer/pull/2833#discussion_r1027027866) retracts precisely that objection. Neither unconditional catch removal nor blanket suppression follows.

**Inspect actual representations and hot paths.** Before rejecting BigInt, an apparently missing value, or a conversion, trace the dependency contract. [Protocol1411](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1411#discussion_r2267940480) explains i64 `valueOf` behavior that invalidates a generic AI warning. For a performance claim or materially changed hot codec, compare equivalent workloads before/after; [ProtoDef176](https://github.com/ProtoDef-io/node-protodef/pull/176#issuecomment-5535944715) requests that evidence. Preserve correctness and report measurement noise. Shorter code, fewer lines, or copying vanilla's implementation shape is not a measured speedup.

**Keep tooling and style requests grounded.** Use the repository's actual lint/module/runtime contract. Explain why dependency, compiler, build, or formatting churn is needed for this change; avoid importing dated preferences as permanent bans. [Mineflayer2921](https://github.com/PrismarineJS/mineflayer/pull/2921#issuecomment-1409768359) distinguishes meaningful changes from unrelated churn. Do not request tests that merely restate a cosmetic edit.

## Decide whether to comment

State the changed line, concrete consequence, and smallest useful correction or evidence request. Label optional cleanup explicitly. If the contract is already preserved, the cost is unsubstantiated, or a maintainer accepted follow-up work, do not manufacture a blocker. Match validation to the disputed behavior; [protocol1283](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1283#discussion_r1454491899) explicitly prefers causal understanding over adding tests for its own sake. This skill grants no permission to publish reviews.
