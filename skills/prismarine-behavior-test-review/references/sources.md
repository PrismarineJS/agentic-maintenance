# Historical support and scope

These examples are discovery evidence with verified account attribution and undisclosed manual authorship. Explicit Astra and other generated feedback is not independent maintainer evidence. Full case records preserve merge outcome, author replies and inspection limits in `implementation/phase3/review_cases.jsonl`.

- [Mineflayer #3392](https://github.com/PrismarineJS/mineflayer/pull/3392) requests an old-fail/new-pass heldItemChanged regression. [#3625](https://github.com/PrismarineJS/mineflayer/pull/3625) later includes packet-facing and direct inventory-update paths. They are one problem family. [World #145](https://github.com/PrismarineJS/prismarine-world/pull/145) places the inside-block raycast case in the existing world suite; [Chunk #241](https://github.com/PrismarineJS/prismarine-chunk/pull/241) requests public model behavior despite a provider being the immediate consumer.
- [Mineflayer #3743](https://github.com/PrismarineJS/mineflayer/pull/3743): prove actual server behavior rather than the fix's packet choice or local flag. [#3740](https://github.com/PrismarineJS/mineflayer/pull/3740): an air target is an invalid bucket fixture; create a solid target, observe the update and use correct world coordinates.
- [prismarine-chunk #232](https://github.com/PrismarineJS/prismarine-chunk/pull/232): maintainer corrects the fixture-origin claim to raw network bytes and asks that the regression distinguish old from new code. Scoped Hypixel roundtrip exclusions remain after excess-data/canonicalization explanation; byte equality is not a universal requirement.
- [Mineflayer #3651](https://github.com/PrismarineJS/mineflayer/pull/3651): awaiting non-Promise chat does not synchronize server state. [#3824](https://github.com/PrismarineJS/mineflayer/pull/3824): reuse condition-aware bounded waits. [#2833](https://github.com/PrismarineJS/mineflayer/pull/2833): error-swallowing objection is withdrawn after distinguishing returned and derived promises.
- [NMP #1383](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1383): repeated configuration accumulates listeners; preserved discussion explains a scoped .once correction, but the final diff is empty. [Mineflayer #3722](https://github.com/PrismarineJS/mineflayer/pull/3722): configuration readiness applies across actions and requires a wider lifecycle contract.
- [Mineflayer #3793](https://github.com/PrismarineJS/mineflayer/pull/3793): local reproduction and packet logs precede retries. [#3811](https://github.com/PrismarineJS/mineflayer/pull/3811): explicit version must not hide failed auto-detection. [#4019](https://github.com/PrismarineJS/mineflayer/pull/4019): a server patch can mask the real failure; retry remains an option with its restart boundary clarified. [minecraft-data #1233](https://github.com/PrismarineJS/minecraft-data/pull/1233): an unrelated reverted-PR CI failure is rerun instead of blamed on the target fix.
- [NMP #1521](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1521): bidirectional chat needs a real server or at least an actual NMP client/server pair. Loopback is an accepted minimum here, not proof of vanilla conformance. [Physics #125](https://github.com/PrismarineJS/prismarine-physics/pull/125): name the real Mineflayer/Pathfinder consumers tested.
- [Mineflayer #3384](https://github.com/PrismarineJS/mineflayer/pull/3384): demonstrate candidate dependencies through a temporary pin and land with the released supporting API. [Registry #26](https://github.com/PrismarineJS/prismarine-registry/pull/26): a login without the intended assertion path is insufficient for a registry roundtrip test.
- [minecraft-data #669](https://github.com/PrismarineJS/minecraft-data/pull/669), [Mineflayer #3222](https://github.com/PrismarineJS/mineflayer/pull/3222) and [NMP #1241](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1241): smoke coverage or desired follow-up tests can coexist with explicit acceptance. [NMP #1283](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1283): reviewer explicitly says further tests are unnecessary for that discussion; understanding the proposed event matters first.
- [prismarine-contribute #2](https://github.com/PrismarineJS/prismarine-contribute/issues/2) makes more tests a priority; [Mineflayer #3271](https://github.com/PrismarineJS/mineflayer/issues/3271) points to an existing test API. Neither mandates wholesale migration. [NMP #372](https://github.com/PrismarineJS/node-minecraft-protocol/issues/372#issuecomment-2106310121) locates auth mocking in prismarine-auth while documenting real external testing barriers.
