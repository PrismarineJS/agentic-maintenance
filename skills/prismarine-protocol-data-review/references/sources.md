# Historical support and scope

These precedents come from the frozen phase3 discovery corpus. Account attribution is verified; manual authorship is not independently established. Explicit agent contributions are excluded from the reasoning below. Related version/replacement PRs count as one family, not independent endorsements. See `implementation/phase3/review_cases.jsonl` for outcome, chronology, revision limits and exact comment links.

- [minecraft-data #721](https://github.com/PrismarineJS/minecraft-data/pull/721): extraction tools, reviewable protocol delta and candidate NMP/Mineflayer tests. [#649](https://github.com/PrismarineJS/minecraft-data/pull/649) requests baseline-copy and change separation; #650 and #661 repeat that workflow in related version work.
- [minecraft-data #1118](https://github.com/PrismarineJS/minecraft-data/pull/1118): update maintained YAML and regenerate JSON. [#1049](https://github.com/PrismarineJS/minecraft-data/pull/1049): generator demand withdrawn for a historical typo; runtime dimension names remain open strings.
- [minecraft-data #884](https://github.com/PrismarineJS/minecraft-data/pull/884): inspect shared item structure embeddings against exact vanilla source. [#898](https://github.com/PrismarineJS/minecraft-data/pull/898): incomplete slot framing can corrupt following elements, while missing recipe variants are expressly deferred.
- [minecraft-data #1154](https://github.com/PrismarineJS/minecraft-data/pull/1154): reuse the correct relative-position bitflags type; nine logical bits still occupy a four-byte integer. [#1180](https://github.com/PrismarineJS/minecraft-data/pull/1180) and [#1127](https://github.com/PrismarineJS/minecraft-data/pull/1127) bound backports by actual introduction history.
- [minecraft-data #971](https://github.com/PrismarineJS/minecraft-data/pull/971): source-level field normalization replaces a proposed feature flag; early approval was superseded. [#1284](https://github.com/PrismarineJS/minecraft-data/pull/1284) preserves named enum representation rather than removing a mapper for numeric callers.
- [ProtoDef #176](https://github.com/ProtoDef-io/node-protodef/pull/176): benchmarks and downstream testing precede approval, but extremeheat's [post-merge objection](https://github.com/ProtoDef-io/node-protodef/pull/176#issuecomment-5651567589) distinguishes rejected symbolic inputs from required unknown-numeric passthrough. A blanket strict-mapper policy would erase that disagreement. [#162](https://github.com/ProtoDef-io/node-protodef/pull/162) additionally compares compiled/interpreted validation.
- [prismarine-chunk #237](https://github.com/PrismarineJS/prismarine-chunk/pull/237): runtimeId and stateId differ; registry enrichment is chosen after comparing ownership alternatives, with test uncertainty acknowledged.
- [NMP #1275](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1275): shared chat/NBT ownership is preferred to copying, while a public NMP export is accepted as a practical migration route. [NMP #1309](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1309) similarly leaves generic codec placement as follow-up.
- [minecraft-data-generator #24](https://github.com/PrismarineJS/minecraft-data-generator/pull/24): existing modules must remain valid, but support for every older version is explicitly unnecessary without a consumer. [Registry #18](https://github.com/PrismarineJS/prismarine-registry/pull/18): documented 1.19+ API availability is accepted instead of building historical fallbacks.
- [NMP #1337](https://github.com/PrismarineJS/node-minecraft-protocol/issues/1337#issuecomment-2452952450): ask for the specific failing packet and dumped buffer; suspected compiler/dependency causes remain hypotheses. [prismarine-contribute package map](https://github.com/PrismarineJS/prismarine-contribute/blob/4317c201c884148c6263de2bdf487f6b6396ef20/info.md) supplies the modular ownership context, not current version guarantees.
