# Evidence and limits

These are paraphrased examples from the September 2026 survey. Ordinary comments are attributed to the named GitHub account; independent manual authorship is generally unverified. Explicitly agent-generated comments are excluded from the historical basis. Source outcomes are recorded in `implementation/phase3/review_cases.jsonl`, separately from whether each concern was resolved.

| Review decision | Supporting examples | Boundary or counterexample |
| --- | --- | --- |
| Start with the actual contract and allow evidence to correct the review. | [Mineflayer #3280](https://github.com/PrismarineJS/mineflayer/pull/3280#issuecomment-1891041198): rom1504 retracts an alleged breaking rename when the original option remains. [Protocol #1263](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1263#issuecomment-1870410070): earlier schema changes invalidate a field-name objection. | A maintainer's initial question is not a settled rule. Read replies and revision chronology. |
| Exercise the real consumer, including candidate dependency changes. | [Mineflayer #3384](https://github.com/PrismarineJS/mineflayer/pull/3384#issuecomment-2156699400): temporary dependency branch enables integration testing. [Registry #26](https://github.com/PrismarineJS/prismarine-registry/pull/26#discussion_r1267908153): login alone does not establish that the changed packet path ran. [ProtoDef #154](https://github.com/ProtoDef-io/node-protodef/pull/154#issuecomment-2156064597): companion NBT consumer can point at the branch. | [Mineflayer #3102](https://github.com/PrismarineJS/mineflayer/pull/3102#issuecomment-1646580592): existing container-suite evidence is accepted for the provider change while extra tests remain desirable. |
| Match validation to the behavioral claim. | [Mineflayer #3743](https://github.com/PrismarineJS/mineflayer/pull/3743#discussion_r2365596080): an activation test must demonstrate an effect. [Mineflayer #3796](https://github.com/PrismarineJS/mineflayer/pull/3796#issuecomment-3717179802): skipping checks or removing candidate dependencies weakens claimed integration evidence. | [ProtoDef #154](https://github.com/ProtoDef-io/node-protodef/pull/154#issuecomment-2448916455) merges with a missing test acknowledged. This is a contextual acceptance, not proof that tests never matter. |
| Proportion architecture demands to the invariant at risk. | [Protocol #1254](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1254#discussion_r1327909079): a narrow client injection point replaces a custom transport's wholesale override. [Mineflayer #3722](https://github.com/PrismarineJS/mineflayer/pull/3722#issuecomment-3209989774): configuration-state suppression is explicitly required beyond a physics-only fix. | [Mineflayer #3003](https://github.com/PrismarineJS/mineflayer/pull/3003#issuecomment-1493432816) accepts a bounded local fix while broader async work is deferred. [Protocol #1277](https://github.com/PrismarineJS/node-minecraft-protocol/pull/1277#pullrequestreview-1799704432) approves despite identified cleanup work. |

The workflow also includes general review practices and explicit user requirements: revision tracking, current-head verification, nonduplicate comments, disclosure of Astra authorship, and publication authorization. These are declared operational rules, not claims of three-reviewer consensus. Karang had no qualifying PR participation in the four-year selected search; older architectural comments appear only as separately dated foundational context.
