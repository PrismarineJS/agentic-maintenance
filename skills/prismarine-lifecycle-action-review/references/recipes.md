## Settings, input and reply lifetime

- [Settings source, #4065](https://github.com/PrismarineJS/mineflayer/blob/b59072e9559a766b3ebe5de714eec4b517750adc/lib/plugins/settings.js): inject the real settings plugin and NMP `src/client/play.js` with a registry-backed event emitter. Capture `settings.viewDistance`, emit `success`, switch to play, call `setSettings({ viewDistance: 'short' })`, emit `start_configuration`. Reviewed output is `[12,8,12]`; a synchronization fix should retain the updated setting. Test a caller-supplied `clientSettings` separately, respecting its intended precedence. The NMP 1.67.0 handler reads that options object on each configuration entry.
- [Input source, #4063](https://github.com/PrismarineJS/mineflayer/blob/fc480ee8c456de87ce77769b31ba8bcf88703043/lib/plugins/physics.js): in the `test/internalTest.js` physics harness supply a loaded chunk and initial position, enable sneak and advance three ticks. Actual 1.20.4 head/base comparison with minecraft-data 3.116.0 found no legacy `entity_action` at head and a write at base. The existing 1.21.4 physics suite still passed nine tests: nearby coverage did not exercise the legacy feature branch.
- [Queued replies, #4107](https://github.com/PrismarineJS/mineflayer/blob/4ac7233799487bc7b105bb8504dd50e04dd9306b/lib/plugins/physics.js): enqueue a relative teleport and ping, cross respawn or configuration, then drain with valid new-world state. Assert that replies do not move the new entity using old coordinates. Separately interleave ping/teleport arrival and tick/fallback drain to inspect ordering. Include ordinary same-session FIFO as a control.
- [Delayed reply, #4099](https://github.com/PrismarineJS/mineflayer/blob/0556385444e76b348b7e16bad9cd476bbda21afc/lib/plugins/physics.js): the existing internal tests for newer-teleport replacement and configuration transition passed at the recorded head. Preserve this positive example; cancellation is not missing merely because a different queue PR has a lifetime defect.

## Actions and re-entry

- [Shared sequence helper](https://github.com/PrismarineJS/mineflayer/blob/fa678c81777cb5584f6fabd4493b4a9716d75d73/lib/plugins/sequence.js), [inventory callers](https://github.com/PrismarineJS/mineflayer/blob/fa678c81777cb5584f6fabd4493b4a9716d75d73/lib/plugins/inventory.js): empty main/off hands emit no use packet. Equipped use/release/place/use/activateBlock/dig-start/dig-finish produced sequences `1,0,2,3,4,5,6` in the focused trace; inspect `generic_place.js` and `place_entity.js` rather than inferring coverage from the helper alone.
- [Instant digging, #4094](https://github.com/PrismarineJS/mineflayer/blob/36e6265f3b23a6fac255443b9041e1090c584cc8/lib/plugins/digging.js): make the instant block update synchronous, start dig B inside `diggingCompleted` for A, then stop B. The reviewed head leaves one B-position listener. Controls: ordinary instant dig emits START only; two physics ticks swing twice during a timed dig; ordinary cancellation rejects and removes the listener. This isolates task ownership without claiming vanilla timing was reproduced.
- [Resource packs, #4104](https://github.com/PrismarineJS/mineflayer/blob/217e7f928f87e973a16115c5047a6586c783b2ed/lib/plugins/resource_pack.js): compare no listener, persistent listener, and a `once` listener that accepts synchronously. Counting listeners after emission can mistake the consumed `once` listener for no handler and autoaccept twice. Check UUID/hash initialization before emission and version-specific response order with actual codecs.

Use NMP's compiled production path for encoding objections. The earlier #4086 numeric `client_command` objection was withdrawn: actual Client/plugin/codec checks accepted numeric zero on 1.8.9, 1.21.4 and 26.1; `gameMode: 0` emitted no command. An isolated ProtoDef interpreter failure was not a production regression. No live vanilla server was run for these focused lifecycle probes.
